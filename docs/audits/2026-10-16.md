## A01 · P1 · 权限检查与执行读取不同规则版本

**触发条件：** 请求进入时能力为只读，同步在权限判断使用的快照与执行引擎读取之间将同名能力替换为写能力。只读 API Key 仍可能执行新版本。

**证据：** [Invoker.java](../../hermit-crab/src/main/java/dev/hermit/crab/runtime/Invoker.java) 93–99 行取 doc/capability 并检查权限；177–185 行只将 Shell/action 名传给引擎。[RuleEngine.java](../../hermit-crab/src/main/java/dev/hermit/crab/engine/RuleEngine.java) 61–67 行重新查注册表。注册表可被 ShellSync 原子替换，这两次读取没有共同快照或版本校验。

探针在 CapabilityGate 回调中切换注册表，确定性模拟这个并发交错。新 action 明确 read_only=false，principal 对其 permits=false，却得到 200 和新版本标记 `new_write`。探针仅返回合成标记，不对真实系统执行写操作；它证明了数据流缺陷，不测量生产竞态发生概率。

**影响：** 只读授权可跨版本失效；HTTP 方法、凭证声明、配置与 MCP 确认也可能基于不同版本元数据。

**建议：** 一次请求携带不可变的已授权 Shell/action 快照到引擎；或在统一版本一致性边界内重新验证权限、方法、声明及确认。不要仅给单次 registry.find 加锁。

**修复验收：** 通过 latch/barrier 控制同步发生在检查与执行之间，验证 HTTP 和 MCP 都只能执行旧快照或拒绝/重试；只读 Key 绝不能执行新写能力。

## A02 · P2 · config 的 secret 字段没有敏感数据保护

**触发条件：** Shell 声明 `config.<field>.type: secret`，操作者通过密码输入控件保存秘密。

**证据：** [ShellParser.java](../../hermit-common/src/main/java/dev/hermit/common/parse/ShellParser.java) 使用同一 FIELD_TYPES 接受 config.secret；[ShellConfigStore.java](../../hermit-crab/src/main/java/dev/hermit/crab/store/ShellConfigStore.java) 直接保存字符串；[ConsoleApi.java](../../hermit-crab/src/main/java/dev/hermit/crab/gateway/ConsoleApi.java) config 查询返回 value。[RuleEngine.java](../../hermit-crab/src/main/java/dev/hermit/crab/engine/RuleEngine.java) 的秘密集合来自 credentials/Cookie，没有把 secret 配置值纳入。

探针保存合成标记，直接 SQL 读取为明文；用 `{{config.access_value}}` 输出到普通字段时也未脱敏。密码输入框不提供加密或输出保护。

**影响：** 使用这个合法声明保存秘密的用户，会在数据库备份和规则输出中暴露秘密。是否发生实际泄露取决于使用的规则与配置，本次没有扫描真实数据。

**建议：** 短期禁止 config.secret 并引导迁移到 credentials；若要支持秘密配置，需要加密存储、只写接口、执行脱敏与旧数据迁移一起设计。本轮文档明确仅将秘密放入 credentials。

**修复验收：** 声明被明确拒绝，或数据库/查询/日志/输出均不出现明文，旧实例迁移可用。

## A03 · P2 · 能力总超时不能限制持续慢速响应

**触发条件：** 上游在 socket 读取超时之前持续发送少量响应字节，但总耗时超过能力预算。

**证据：** [HttpCalls.java](../../hermit-crab/src/main/java/dev/hermit/crab/engine/HttpCalls.java) `once` 将剩余时间用于 responseTimeout，`readBody` 循环只检查 5 MiB 大小，不检查 deadline。`RuleEngine.runSteps` 只在步骤开始检查总 deadline，最后一步结束后仍可返回成功。

探针以 EngineSettings 配置 500ms 预算，模拟服务每 80ms 发送一字节，约 2.1 秒后得到 success=true。500ms 是测试加速值；正式配置以整数秒设置，但同样的实现缺口仍存在。

**影响：** 单请求及账号会话锁可被慢速上游长时间占据，调用耗时超过声明预算；数据量小也可触发。

**建议：** 为总 deadline 提供真正的请求取消机制，覆盖连接/响应体读取/重定向；读取过程中与输出前再校验剩余预算。仅增加循环检查不能保证阻塞 read 被及时中断。

**修复验收：** 慢速分块响应应在预算附近结束并返回 TIMEOUT，释放连接与账号锁；同时覆盖连接阶段、跳转和最后一步。

## A04 · P2 · Cookie 脱敏历史重复累积

**触发条件：** 长期运行的账号反复发出 HTTP 请求，即使 Cookie 完全不变。

**证据：** [SessionManager.java](../../hermit-crab/src/main/java/dev/hermit/crab/engine/SessionManager.java) 154–170 行每次 persist 都把全部 Cookie 值 append 到 ArrayList，读取时又整体复制；没有去重/容量边界。失效重登的 markLoggedOut 也不清除此历史，显式 invalidate 才清除。

探针只有 1 个固定 Cookie，执行 1000 次持久化后历史长度为 1000。

**影响：** 正常业务调用即可让每个账号的常驻列表不断增长，并增加复制/脱敏开销。暂时不需要恶意请求就能累积资源压力。

**建议：** 对历史值去重并设置合理生命周期/容量，保留当前执行仍需要脱敏的旧 Cookie；避免每次处理复制无界历史。

**修复验收：** 相同 Cookie 的重复请求不会增长；轮换 Cookie 时仍能脱敏当前/必要历史值且内存有界。

## A05 · P2 · 幂等锁不随请求完成或缓存清理回收

**触发条件：** POST 调用持续使用不同 Idempotency-Key。

**证据：** [Invoker.java](../../hermit-crab/src/main/java/dev/hermit/crab/runtime/Invoker.java) 143–154 行 computeIfAbsent 创建锁，类内无移除路径；[CrabRuntime.purgeExpired](../../hermit-crab/src/main/java/dev/hermit/crab/runtime/CrabRuntime.java) 只清数据库记录。探针完成 100 个唯一键的请求并删除对应缓存后，锁 Map 仍为 100。

**影响：** 幂等数据库 24h TTL 无法约束锁 Map，常驻进程内存随历史唯一键总数增长。

**建议：** 使用固定数量条带锁，或有正确引用计数的锁池；直接在 finally remove 可能使等待旧锁和拿新锁的线程并发执行相同键，需要设计并发安全的回收。

**修复验收：** 大量唯一键后锁资源有界；同一键并发调用仍只执行一次，过期重试正确。

## A06 · P2 · 回滚事件重报不幂等

**触发条件：** Reef 已提交上报事务，但 HTTP 成功响应丢失，Crab 重发同一批次。

**证据：** [ReportSender.java](../../hermit-crab/src/main/java/dev/hermit/crab/report/ReportSender.java) 只有收到 2xx 才 ack 队列；[ReportIngestService.java](../../hermit-reef/src/main/java/dev/hermit/reef/tide/ReportIngestService.java) 98–108 行对回滚事件无条件 INSERT；[表结构](../../hermit-reef/src/main/resources/db/migration/V1__init.sql) 没有事件唯一键。失败报告的实例+trace 去重不适用于回滚事件。

探针在独立事务内摄入相同批次两次，1 个逻辑事件得到 2 行。与实际网络重试具有相同入库路径，但未模拟真实网络丢包。

**影响：** 回滚列表出现重复，人工判断回滚频率时可能被误导；无法区分重试与真实重复事件。

**建议：** 为回滚事件引入持久化稳定 ID，并在 Reef 建唯一约束、幂等写入；兼顾 strict DTO 的两端协议升级与 Flyway 迁移。

**修复验收：** 顺序/并发重复批次均只保存一次；两个真实独立回滚事件仍分别保留，覆盖 H2 与 MySQL。

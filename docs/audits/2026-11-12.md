## 本轮发现与修复

| # | 问题 | 复现/证据 | 修复 |
| --- | --- | --- | --- |
| 1 | Crab 控制台可被 DNS rebinding 接管：只看套接字回环和 `X-Hermit-Console`，不看 `Host`/`Origin` | 用临时 Crab 实测：`Host`/`Origin` 为 `attacker.example` 时 `POST /console/api/apikeys` 成功创建全权限 Key；同一 `Origin` 访问 `/mcp` 为 403 | `/console/**` 要求 `Host` 和带了的 `Origin` 是 `localhost`、`127.0.0.1` 或 `[::1]`，端口不比较。`ConsoleHostTest` |

| 4 | MCP 上游读超时与定时取消同一时刻到期：读超时先到时报成「上游连接失败。」，也不发 `notifications/cancelled` | 完整 verify 时 `McpForwardTest.limitsSizeTimeoutAndAddresses` 失败；单独跑 3 次都失败 | 读超时晚 1 秒；仍先到时按到期的是哪一个记原因并补发取消。原测试单独跑与整类跑均稳定通过 |

## 未处理与边界

- 多个 Reef 进程共用一个库时，登录排队只在各自进程内有效。
- `/openapi.json` 不需要 API Key，列出能力目录；本轮没有改。
- 上报入库的失败去重仍是先查后写，同一实例并发上报时可能撞唯一键后整批重试。
- 脚本内存预算按分配量计，不是进程级隔离；同一 JVM 里其它请求仍会受大量分配影响。
- 未在浏览器里点选，未启动 MySQL、Compose 或真实 MCP 客户端，未做压测。

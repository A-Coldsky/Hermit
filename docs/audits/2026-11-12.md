# Hermit 代码复核（2026-11-12）

基线：`main` 的 `8e78eea`。修复在分支 `fix/code-review-2026-11-12` 上，每项一个提交，带回归测试。日期为北京时间。

范围：Crab 网关、控制台鉴权、`Invoker` → `RuleEngine` → `HttpCalls`、会话与凭证加密、签名包、同步、MCP（含 OAuth 与写规则工具）、Reef 安全链、发布、上报与 Tide 查询、容器入口。本次不是形式化验证或完整渗透测试，也没有做依赖 CVE 扫描。

| 项 | 现状 |

| A06 回滚事件重报 | 此前已修：V3 增加 `event_id` 和唯一索引 |

## 本轮发现与修复

| # | 问题 | 复现/证据 | 修复 |
| --- | --- | --- | --- |
| 1 | Crab 控制台可被 DNS rebinding 接管：只看套接字回环和 `X-Hermit-Console`，不看 `Host`/`Origin` | 用临时 Crab 实测：`Host`/`Origin` 为 `attacker.example` 时 `POST /console/api/apikeys` 成功创建全权限 Key；同一 `Origin` 访问 `/mcp` 为 403 | `/console/**` 要求 `Host` 和带了的 `Origin` 是 `localhost`、`127.0.0.1` 或 `[::1]`，端口不比较。`ConsoleHostTest` |
| 2 | 开发者模式下 `conch_trial_run`、覆盖已有本地包的 `conch_save_local` 不看 Key 范围；试跑也不要求破坏性确认 | 实测：只点名 `alpha_pkg` 的 Key，HTTP 调 `beta_pkg` 是 403，但 MCP 试跑成功执行了 `beta_pkg` 的写能力（客户端不支持确认） | 覆盖和试跑要求 Key 能调用该包；`effectiveConfirm()` 的试跑要 elicitation。`AuthoringMcpTest` 新增 2 项 |
| 3 | MCP 确认与执行可能不是同一版本（A01 剩余部分） | 代码路径：`McpCalls` 按 `catalog.find` 的 action 决定确认，`Invoker` 对 MCP 不再检查确认 | 确认过的调用带上确认时的 `ConchDoc`，`Invoker`/试跑发现注册表换了就 `CONFLICT`。`AuthoringMcpTest` 新增 2 项 |
| 4 | MCP 上游读超时与定时取消同一时刻到期：读超时先到时报成「上游连接失败。」，也不发 `notifications/cancelled` | 完整 verify 时 `McpForwardTest.limitsSizeTimeoutAndAddresses` 失败；单独跑 3 次都失败 | 读超时晚 1 秒；仍先到时按到期的是哪一个记原因并补发取消。原测试单独跑与整类跑均稳定通过 |
| 5 | 幂等条带锁包住整个上游调用 | 代码路径：`Invoker.replayOrExecute` | 每个键一个进行中标记，结束即移除。`IdempotencyInFlightTest` |
| 6 | Tide `summary`/`failures` 把最长 400 天的全部明细读进内存再分组 | 代码路径：`TideQueryService` | 在库里 `GROUP BY`，每组最新 5 条用 `ROW_NUMBER()`。响应不变。`TideQueryTest` 新增 1 项 |
| 7 | 控制台批量写配置逐项生效 | 代码路径：`ConsoleApi.writeConfig` | 先全部校验，再一个事务写入。`ConsoleConfigTest` 新增 1 项 |
| 8 | Reef 改口令或重置口令后旧 JWT 仍有效 8 小时 | 文档原写明「改口令不使已发出的 JWT 失效」 | V8 `token_version`，JWT 带 `tv`；管理端改完密码后重新登录。`ReefUsersAndTokensTest`、`reef-password.test.ts` |
| 9 | Reef 登录失败计数先查后写，并发请求可在锁定前多猜 | 代码路径：`LoginService.login` | 同一用户名在本进程内排队，整段一个事务。`AdminApiTest` 新增并发用例 |
| 10 | 容器首次启动可能经远端明文 HTTP 登录并取签名公钥（信任根） | 代码路径：`deploy/crab-entrypoint.sh` 的 `fetch_pub` | 只在 https 或本机地址自动取；否则要 `HERMIT_REEF_PUBLIC_KEY_FILE`，或显式 `HERMIT_REEF_ALLOW_INSECURE_KEY_FETCH=1`。`CrabEntrypointTest` 新增 2 项 |
| 11 | 删除账号后，锁、连接池、MCP 上游会话、OAuth 刷新锁一直留在内存；过期的控制台会话只在校验时删除 | 代码路径：`SessionManager`、`McpUpstreamSessions`、`McpOAuth`、`ConsoleSessions` | 删账号时清掉；签发控制台会话时清理过期项。`SessionManagerTest`、`ConsoleSessionsTest` |
| 12 | Rhino 脚本内存没有上限，单次巨大分配的 `OutOfMemoryError` 抛到 Jetty 线程 | 代码路径：`ScriptStep` | 按执行线程累计分配（默认 256 MiB）停下，OOM 在步骤里接住，都是「脚本内存超限」。`ScriptStepTest` 新增 1 项 |
| 13 | 同步下载时持有对象锁，控制台列表和详情跟着卡住，最长到 Reef 超时 | 代码路径：`ConchSync` | 改成 `ReentrantLock`，只读显示最多等 2 秒，等不到就直接读。`ConchSyncDisplayTest` |

## 未处理与边界

- 多个 Reef 进程共用一个库时，登录排队只在各自进程内有效。
- `/openapi.json` 不需要 API Key，列出能力目录；本轮没有改。
- 上报入库的失败去重仍是先查后写，同一实例并发上报时可能撞唯一键后整批重试。
- 脚本内存预算按分配量计，不是进程级隔离；同一 JVM 里其它请求仍会受大量分配影响。
- 未在浏览器里点选，未启动 MySQL、Compose 或真实 MCP 客户端，未做压测。
